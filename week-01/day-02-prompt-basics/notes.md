# Day 2 学习笔记 — Prompt Engineering 基础

## 📊 今日实测数据

### 1️⃣ Zero-shot vs Few-shot(10 条评论分类)

| 方法 | 准确率 | 错样本 |
|------|:----:|------|
| Zero-shot | 9/10 = **90%** | 「外观还行,功能一般,价格略贵」误判负面 |
| Few-shot (3 examples) | 10/10 = **100%** | 全对 |
| **提升** | **+10%** | — |

**关键发现**:那条错样本是**边界 case** —"略贵"是负面词,但"外观还行 + 功能一般"是中性基调。Zero-shot 没 anchor → 被"略贵"带偏。Few-shot 的第 3 个示例「外观一般 + 没什么惊喜 → 中性」结构高度对应,模型立刻 anchor。

> 💡 **Few-shot 的核心价值不是"教分类",是"给边界 case 一个 anchor"**。

---

### 2️⃣ 模糊指令 vs 清晰指令(token 经济学)

| | Prompt 字符 | 输出字符 | 总字符 | JSON 解析 |
|---|---:|---:|---:|:---:|
| 模糊指令 | 183 | 900(markdown 表格) | 1083 | ❌ |
| 清晰指令 | **716** (+533) | **351** (-549) | **1067** | ✅ |

**关键发现**:
- 多花 533 prompt 字符,**省下 549 输出字符**
- 总字符基本持平 / 略省
- 清晰版输出**直接可消费**,不用写正则
- 一旦开 Prompt Caching(W4 学),清晰指令的固定部分可缓存,长期成本骤降

> 💡 **多花 prompt token 换 deterministic 输出,几乎总是划算**。

### 3️⃣ 角色 × 格式矩阵(导购应用 UX 实验)

#### 角色对比(固定纯文本格式)

| 角色 | 字数 | 推荐数 | 风格特征 |
|------|:---:|:---:|------|
| 默认无角色 | ~600 | ~13 项(4 大类) | 撒胡椒,不聚焦 |
| 中立购物顾问 | ~500 | 6 + 避坑 | 理性、有结构 |
| **10 年资深买手** | **~300** | **3 精选** | **精炼、有情感钩子** |

**🎁 金句涌现**:资深买手主动建议加"手写卡片:感谢你让家如此温暖" — 默认 prompt 不会有这种细节。

#### 格式对比(固定资深买手角色)

| 格式 | 用途 | 集成成本 |
|------|------|------|
| 纯文本 | 对话流 | 低(直接显示) |
| Markdown | 文档级阅读 | 中(需要 markdown 渲染器) |
| **JSON 卡片** | **前端组件渲染** | **高价值**(`v-for` 直接渲染) |

JSON 输出 5 个 SKU,字段齐全(name / price / reason / target),**直接对接现有导购插件前端**。

## 💡 三个核心洞察(博客 #2 主线)

### 洞察 1:Few-shot 是"边界 case 的 anchor",不是"教分类"

```python
# ❌ 错误理解
"我给 3 个例子,模型就学会了分类"

# ✅ 正确理解
"我给 3 个例子,其中 1 个的'句式结构'匹配了边界 case → 模型 anchor 到正确类别"
```

**实战指导**:挑 Few-shot 例子时,优先挑**最像 production 中边界 case 的样本**,不要挑"最典型"的样本。

---

### 洞察 2:清晰指令的"5 要素"框架

```
1. 角色(Role)         — "你是电商数据分析师"
2. 任务(Task)         — "提取结构化属性"
3. 格式(Format)       — "返回合法 JSON"
4. 字段(Schema)       — "必含 brand/model/colors/..."
5. 异常(Fallback)     — "缺失字段填 null"
```

5 要素齐全 → JSON 解析率 100%
5 要素只用 2-3 个 → 解析率随机

---

### 洞察 3:角色 prompt 的"涌现"效应

| 角色描述 | 涌现的细节 |
|---------|----------|
| 10 年资深买手 | 主动建议"手写卡片:感谢你让家如此温暖" |
| 中立购物顾问 | 主动加"避坑建议"段落 |
| 默认无角色 | 撒胡椒,无独特细节 |

**为什么角色描述有效?**
- 模型从训练数据中学过"特定角色的说话方式"
- "10 年经验"这种**数字化锚点**比"经验丰富"更有效
- "温暖且专业"这种**复合形容词**会引导出特定语气
